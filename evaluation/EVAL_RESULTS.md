# COCO-Tasks evaluation — our lightweight pipeline vs the paper

Metric: AP@0.5 per task against the preferred-object annotations, averaged over
the 14 tasks (mAP@0.5) — the metric of Sawatzky et al., CVPR 2019.

Our probability is `MiniLM(task, class_name)` read from the **deployed INT8
package** (`minilm_task_class_scores.json`, 14×80, generated by running the same
binary the board runs). Following the paper, the confidence used for AP is the
detection score multiplied by that probability; on ground-truth boxes there is
no detection score, so the probability is used directly.

## Results

| box source | **ours** | paper: pick-best-class | ranker | no visual input (T3 g) | classification | proposed+fusion |
|---|---|---|---|---|---|---|
| ground-truth boxes | **0.648** | 0.386 | 0.564 | 0.589 | 0.616 | 0.742 |
| Faster-RCNN detections *(the paper's own file)* | **0.288** | 0.141 | 0.091 | 0.237 | 0.288 | 0.326 |
| our YOLOv8n detections | *pending* | — | — | — | — | 0.332 (their YOLOv2) |

### The headline

On **identical Faster-RCNN detections**, our ranker reaches **0.288 mAP@0.5** —
equal to their *classification* baseline, which uses ResNet-101 visual features
— and **88% of their full GGNN method (0.326)**.

It does that with no visual input at all: the ranker sees a task string and a
class *name*, never a pixel. That is why the interesting comparison is their
Table 3 row (g), "no visual input", at 0.237. **We beat their own no-visual
ablation by 0.05**, and the reason is architectural: they encode the class as a
one-hot id, we encode it as *language*. "wine glass" and "cup" are near each
other in a sentence embedding in a way that class ids 46 and 47 are not, and
the paper's Figure 1 argument — use a cup when no wine glass is present — is
exactly that kind of semantic neighbourhood.

utensils, which is where a class-level ranker has least to say.

## How much to trust these numbers

**AP implementation, validated against a published figure.** I reproduced the
paper's *pick-best-class* baseline — rank classes by train-split preference
rate, then per image keep only the highest-rated class present — and got
**0.339 against their published 0.386**. Close enough to say the AP code is in
the right regime, not close enough to call it exact; the residual is probably
their support threshold and class-ranking details, which the paper does not
fully specify. Reproduce with `--method pickbest`.

So: treat the absolute numbers as **±0.05**. The comparisons *on identical
detections* are firmer than that, because the same AP code scores both.

**Tie ordering.** Every instance of a class gets an identical score from us, so
AP depends slightly on how ties are ordered. Measured over 4 shuffles: 0.6464,
0.6492, 0.6487, 0.6493 — mean 0.648, spread 0.003. Natural annotation order
gives 0.658; the table above quotes the conservative shuffled mean.

**What the gap on ground-truth boxes means.** 0.648 vs their 0.742 is the price
of having no instance-level discrimination. Figure 3 of the paper turns on
exactly the cases we cannot do: the handier chair over the table, one bed over
another, the real toilet rather than its reflection. Our score is identical for
every instance of a class, and we break ties by detection confidence.

## Still to run: our own detector

The YOLOv8n column needs the COCO val2014 images and ultralytics, so it has to
run on the Windows PC:

```
cd D:\DVCon\datasets
python eval_coco_tasks.py --root D:\DVCon\datasets --boxes yolov8n --imgsz 128 --out eval_yolo128.json
python eval_coco_tasks.py --root D:\DVCon\datasets --boxes yolov8n --imgsz 192 --out eval_yolo192.json
```

~12,588 images per pass; minutes on a GPU, longer on CPU. Add `--limit 200` for
a quick estimate first.

**Caveat to state when reporting it:** that mode runs ultralytics FP32, while
the board runs our INT8 export at reduced resolution. INT8-vs-FP32 tracked
closely on the two test images (bus @256: FP32 `bus 0.886, person 0.825` vs INT8
`bus 0.861, person 0.804`), but it is an approximation, and the honest label is
"YOLOv8n FP32 detections at 128 px", not "the deployed pipeline".
